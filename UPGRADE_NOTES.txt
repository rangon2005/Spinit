Spinit 2.0 - Matchmaking Reliability Patch

Fixed the specific bug where one device could play the connected sound but remain on “Finding your match”.

Main fixes:
1. PeerJS client data listener is registered BEFORE the connection-open handler, preventing the first host state packet from being missed.
2. Client requests a fresh state snapshot immediately after opening and again at short intervals during the lobby-sync window.
3. Host responds to stateRequest with a fresh authoritative state snapshot.
4. Existing matchAck/repeated-state handshake remains active as an additional recovery layer.
5. WebSocket matchmaking remains immediate FIFO-style: matched entries are removed immediately and no full-queue shuffle is performed.
6. No TURN secrets are placed in frontend code.

Important:
- This improves reliability and pairing speed substantially for a single Render server instance.
- True horizontal 20k+ concurrent scaling across multiple backend instances still requires shared matchmaking state (for example Redis) plus load balancing/sticky or shared signaling strategy.
- The ZIP was syntax-checked with Node for the inline JavaScript and server.js. Full production WebRTC runtime testing cannot be performed inside this build environment.
